Benchmark

Seberapa cepat backend native JRG dibanding C dan Go, dan cara mengukurnya sendiri.

Angka di bawah dari backend LLVM (--emit-llvm), diukur di Intel i5-1235U dengan clang 21, rustc 1.97, dan Go 1.26. Tiap angka adalah waktu terbaik dari enam putaran, dijalankan di satu inti CPU.

KernelJRG (ms)C (ms)JRG : C
numeric_kernel7327480,98
call_recursion5955891,01
struct_particles10449811,06
array_sort10608801,20
match_dispatch7885851,35
mixed_report5232432,15
string_ops5161473,51

Ringkasnya: setara C untuk angka dan pemanggilan fungsi, sedikit di belakang untuk struct, array, dan match, dan jelas lebih lambat untuk pengolahan teks. Dibanding Go, JRG menang di tiga kernel (struct_particles 5,8 kali, call_recursion 1,5 kali, match_dispatch 1,45 kali), seri di dua, dan kalah di dua.

Selisih di string_ops datang dari teks sementara yang belum dibebaskan selama program berjalan; itu pekerjaan berikutnya untuk backend ini.

Mengukur sendiri

Untuk interpreter dan VM ada sembilan kernel tersendiri:

Perbedaan di bawah sekitar 6–10 persen tidak bisa dibedakan dari derau pengukuran di mesin biasa. Untuk membuktikan sebuah perubahan lebih cepat, hitung instruksinya dengan valgrind --tool=callgrind, jangan cuma membandingkan jam.

Bahasa

Konkurensi

Goroutine, channel, select, Future, dan alat sinkronisasi.

Model konkurensi JRG mirip Go: kerjakan sesuatu di goroutine, lalu berkomunikasi lewat channel. Tiap goroutine adalah thread sistem operasi sungguhan, jadi cocok untuk puluhan sampai ratusan tugas, bukan jutaan.

spawn dan channel

spawn { … } (atau go f(x)) menjalankan blok di goroutine baru. make_chan(tipe, kapasitas) membuat channel; c <- v mengirim, <-c menerima.

Variabel yang dipakai di dalam spawn disalin saat goroutine dibuat. Program menunggu semua goroutine selesai sebelum berakhir, jadi tidak ada keluaran yang hilang karena main selesai duluan.

select

select menunggu beberapa channel sekaligus dan mengambil yang pertama siap. Cabang default membuatnya tidak menunggu.

Future dan Task

Untuk pola "mulai sekarang, ambil hasilnya nanti", pakai Future::new(fungsi, argumen…) lalu future::await.

Hasil sebuah Future cuma bisa diambil sekali; mengambilnya lagi adalah galat. Fungsi lain di keluarga ini: future::all, future::race, future::timeout, future::try_get, future::is_done, Task::spawn, dan task::join. Kalau fungsi di dalam Future gagal, galatnya muncul di tempat hasilnya diambil.

Atomic dan Mutex

Nilai biasa tidak pernah berbagi, jadi untuk keadaan bersama antar-goroutine JRG punya dua pegangan: Atomic (bilangan bulat yang aman ditambah dari banyak thread) dan Mutex (kunci).

Menyalin Atomic atau Mutex menyalin pegangannya, jadi semua salinan menunjuk keadaan yang sama. with_lock melepas kuncinya sendiri, termasuk kalau fungsinya gagal.

Yang tidak ada

JRG tidak punya async/await. Goroutine-nya thread sungguhan, bukan tugas ringan, dan sintaks async akan menjanjikan biaya yang tidak sesuai kenyataannya. Untuk menunggu banyak hal sekaligus, pakai channel, select, atau future::all.

JRG 10 · More JRG

When the Answer Might Not Exist

How JRG handles "not found" and "failed" — without ever handing over a fake value that looks like an answer.

reliabilityThe problem being solved

What should a search function return when the thing it looks for is not there? Many languages answer null — and that is where the trouble starts, because null looks like an ordinary value until the program has already used it.

JRG answers differently: such a function returns an Option, which holds one of two things — Some(value) if it was found, or None if it was not.

Taking the value out safely

WayIf there is a valueIf it is empty
x.unwrap_or(fallback)The valueThe fallback you choose
x.is_some()truefalse
matchThe Some(v) armThe None arm

The short form: ??

a ?? b means "use a if it has a value, otherwise use b". The difference from unwrap_or: b is only computed when it is actually needed.

Result: success, or failure with a reason

When a failure has a cause that needs explaining, JRG uses Result: Ok(value) or Err(reason).

Passing a failure on with ?

Writing a match for every call is tiring. The ? mark means: "if this failed, stop this function and pass the error upward".

This is why ? does not open a branch

In JRG the question mark already has this job — passing errors on. That is why the short form of a branch uses $, not ? as in other languages.

Why not just nil

If a function may answer nil for "not found", then nil has two meanings: “not there” and “there, but empty”. Two different situations with the same answer — and the program cannot tell them apart.

Some(nil) ≠ None
Some(nil) → there is a value, it happens to be empty
None → there really is nothing

Quiz 1

What does [1,2].get(99) return?

Exactly — None, which you have to open before using.

JRG uses Option for things that might not be found.

Quiz 2

What does ? at the end of a function call mean?

Right.

The short form of a branch in JRG is $.

Quiz 3

Why is None better than nil for "not found"?

Exactly — and two meanings in one answer is a source of bugs that are hard to track down.

Think: what happens when the value stored really is nil?

Practice on your own

1. Write a function root(n) that refuses negative numbers using Result.

2. Take element 5 of an array with 3 elements, with a fallback of 0.

Answer 1: if n < 0 { return Err("square root of a negative number") } then return Ok(math::sqrt(n)).
Answer 2: a.get(5).unwrap_or(0), or a.get(5) ?? 0.
